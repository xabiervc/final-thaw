## 2. GAMEPLAY EXCELLENCE ENHANCEMENTS

### 2.1 Puzzle Design Philosophy

**Current**: Fixed solutions, readable, deterministic.

**Enhanced**: Apply **Portal 2 Design Philosophy**:

**Three-Act Puzzle Structure**:
1. **Teach**: Introduce mechanic in safest possible context
2. **Test**: Combine with previous mechanics, increase complexity
3. **Twist**: Subvert expectation, force player to rethink

**Example Implementation** (Dam Level):
- **Teach**: Player encounters simple valve—turn to redirect water
- **Test**: Multiple valves must be turned in sequence while avoiding rising water
- **Twist**: One valve appears to work same way but actually reverses flow direction (telegraphed by different color/label)

**Quality Standards**:
- Every puzzle solvable through observation alone (no trial-and-error)
- Wrong input resets local mechanism in <3 seconds (no long penalties)
- Solution feels "inevitable" in hindsight
- No puzzle requires frame-perfect timing
- Optional hint system (3 levels: off, contextual, full solution)

---

### 2.2 Combat Flow Enhancement

**Current**: Deterministic beat-em-up with light/heavy/combo/dodge/block.

**Enhanced**: Apply **Hades Combat Philosophy**:

**Core Improvements**:
1. **Impact Weight**: Every hit has visible, audible, tactile feedback
   - Hit flash (100ms white flash on enemy)
   - Screen shake (subtle, 2-3 pixels, optional reduction in settings)
   - Particle burst (directional, matches attack type)
   - Sound design (distinct per enemy type, per attack type)

2. **Flow State Inducers**:
   - Attack chaining: Successful combos build "momentum meter"
   - Momentum increases movement speed slightly (5-10%), damage slightly (10-15%)
   - Taking damage resets momentum (creates risk/reward)
   - Visual indicator: Subtle glow around Marcus, intensifies with momentum

3. **Environmental Mastery**:
   - Every arena has 2-3 "masterable" elements (throwable objects, cover positions, elevation)
   - Players who learn arena layout gain significant advantage
   - Speedrunners can use environmental kills for time saves

4. **Enemy Telegraph Enhancement**:
   - **Scavenger**: Wind-up = 400ms (arm raises, red glow), Strike = 150ms, Recovery = 300ms
   - **Enforcer**: Wind-up = 600ms (both arms raise, orange glow), Block = instant, Counter = 200ms
   - **Marksman**: Aim = 800ms (laser sight visible, beeping), Shot = instant, Reposition = 500ms
   - **Shield**: Bash = 500ms (shield glows, steps back), Block = constant frontal immunity, Stun = 2s after flank

**Technical Implementation**:
```gdscript
# Attack data structure
const ATTACK_DATA = {
    "light": {"startup": 100, "active": 150, "recovery": 200, "damage": 25, "knockback": 50},
    "heavy": {"startup": 300, "active": 200, "recovery": 400, "damage": 60, "knockback": 150},
    "combo_3": {"startup": 150, "active": 180, "recovery": 250, "damage": 40, "knockback": 80}
}

# Momentum system
var momentum = 0.0
const MOMENTUM_GAIN_PER_HIT = 0.15
const MOMENTUM_DECAY_PER_SECOND = 0.05
const MOMENTUM_MAX = 1.0

func on_hit():
    momentum = min(momentum + MOMENTUM_GAIN_PER_HIT, MOMENTUM_MAX)
    update_momentum_visual()

func on_take_damage():
    momentum = 0.0
    update_momentum_visual()

func get_damage_multiplier():
    return 1.0 + (momentum * 0.15)  # Up to 15% bonus
```

### 2.3 Character Switching Enhancement

**Current**: Switch via input, inactive character waits safely.

**Enhanced**: Apply **It Takes Two (Single-Player) Philosophy**:

**Emotional Resonance**:
- Switching is not just mechanical—it reflects growing trust
- **Act I**: Switching is clunky, limited (only at designated points)
- **Act II**: Switching becomes smoother, more frequent
- **Act III**: Switching is seamless, required for complex coordination

**Mechanical Improvements**:
1. **Switch Cooldown**: 2 seconds (prevents spam, makes switching intentional)
2. **Switch Visual**: Quick 0.5s fade effect, camera pans to new character
3. **Inactive Character**: Becomes holographic, invulnerable, follows 3-5 meters behind
4. **Active Character**: Full control, camera follows

**Synergy Combos** (Act III only):
- **Elena hacks shield → Marcus flank-attacks**: Shield down for 5s, Marcus deals 2x damage
- **Marcus throws Elena → Elena reaches high terminal**: Elena airborne 2s, lands safely
- **Elena freezes water → Marcus crosses**: Water solid 8s, Marcus runs across
- **Marcus creates distraction → Elena sneaks past**: Enemies look away 6s, Elena undetected

**Technical Implementation**:
```gdscript
# CharacterSwitchController
var can_switch = true
var switch_cooldown = 2.0
var last_switch_time = -999.0

func try_switch():
    if Time.get_time_since_startup() - last_switch_time >= switch_cooldown:
        perform_switch()
        last_switch_time = Time.get_time_since_startup()
    else:
        show_cooldown_indicator()

func perform_switch():
    # 0.5s fade transition
    tween.fade(0.0, 0.25)
    await get_tree().create_timer(0.25).timeout
    
    # Swap active character
    active_character = (active_character == "elena") ? "marcus" : "elena"
    update_camera_target()
    
    # Fade back in
    tween.fade(1.0, 0.25)
    await get_tree().create_timer(0.25).timeout
```

### 2.4 Accessibility Excellence

**Target**: Match *The Last of Us Part II* accessibility standard.

**Visual Options**:
- **Colorblind Modes**: 12 types (Deuteranopia, Protanopia, Tritanopia, each with mild/moderate/severe)
- **UI Scale**: 75%, 100%, 125%, 150%, 175%, 200%
- **High Contrast Mode**: Black/white/yellow palette, 90%+ contrast ratio
- **Reduced Motion**: Disables camera shake, screen effects, particle systems
- **Reduced Weather**: 50%, 75%, 100% particle density
- **Screen Reader Support**: All UI elements readable by OS screen readers

**Audio Options**:
- **Subtitle Size**: Small, Medium, Large, Extra Large
- **Subtitle Color**: White, Yellow, Cyan, custom picker
- **Subtitle Background**: None, Semi-transparent, Solid black
- **Speaker Labels**: On/Off (shows character name before dialogue)
- **Visual Sound Cues**: Directional indicators for footsteps, gunfire, important sounds
- **Audio Description**: Optional narration for cinematics (describes visual action)

**Motor Options**:
- **Full Control Remapping**: Every input individually remappable (keyboard, mouse, controller)
- **Toggle/Hold Options**: For sprint, aim, block, interact
- **Auto-Run**: Character continues moving without holding input
- **Aim Assist Levels**: 0%, 25%, 50%, 75%, 100%
- **Slow Motion Mode**: 0.5x, 0.75x, 1.0x (for combat, puzzles, platforming)
- **One-Handed Control Scheme**: All inputs accessible with one hand

**Cognitive Options**:
- **Puzzle Hint System**: Off, Contextual (subtle highlights), Full Solution (shows exact steps)
- **Extended Time Limits**: 1x, 1.5x, 2x, infinite (for timed puzzles)
- **Objective Marker**: Always-on option, pulsing indicator, off
- **Quest Log**: Detailed step-by-step breakdown, can be expanded/collapsed
- **Checkpoint Frequency**: Standard, Frequent (every 2-3 min), Manual save only

**Implementation Priority**:
1. **Core** (Phase 0-1): Control remapping, UI scale, subtitle options
2. **Essential** (Phase 2-5): Colorblind modes, high contrast, reduced motion
3. **Comprehensive** (Phase 6-10): Visual sound cues, aim assist, puzzle hints
4. **Complete** (Phase 11-16): Screen reader, audio description, one-handed scheme

**Testing Requirement**: Disabled gamers must be involved in playtesting from Phase 3 onward. Not as afterthought— as core design input.

# Combat intensity layers
var combat_intensity = 0  # 0 = none, 1 = low, 2 = medium, 3 = high

### 5.2 Save System Robustness

**Target**: Never lose player progress, ever.

**Implementation**:
```gdscript
# Triple-save system
func save_game(slot = "autosave"):
    # 1. Write to temp file first
    var temp_path = get_save_path(slot) + ".tmp"
    var data = serialize_game_state()
    
    var file = FileAccess.open(temp_path, FileAccess.WRITE)
    file.store_var(data)
    file.close()
    
    # 2. Backup existing save
    var save_path = get_save_path(slot)
    if FileAccess.file_exists(save_path):
        DirAccess.copy_absolute(save_path, save_path + ".bak")
    
    # 3. Move temp to actual save (atomic on most filesystems)
    DirAccess.rename_absolute(temp_path, save_path)
    
    # 4. Verify save integrity
    if not verify_save(slot):
        # Restore from backup if corrupted
        DirAccess.copy_absolute(save_path + ".bak", save_path)
        log_error("Save corrupted, restored from backup")

func verify_save(slot):
    var data = load_save(slot)
    return data != null and data.has("checksum") and data.checksum == calculate_checksum(data)
```

**Save Frequency**:
- **Autosave**: Every 30 seconds during gameplay
- **Checkpoint**: After every major event (puzzle solved, arena cleared, boss defeated)
- **Manual**: Player can save anytime (except during cinematics/combat)
- **Cloud**: Optional cloud save sync (Steam Cloud, etc.)
